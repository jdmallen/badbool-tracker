# Sync backend (Azure Functions)

Optional. The site works fully with `localStorage` alone; this adds GitHub sign-in and
cross-device sync via Azure Static Web Apps (SWA) + Azure Table Storage. See
`../PLAN-cloud-sync.md` for the full design.

## What's here

- `src/functions/progress.js` — `GET`/`PUT`/`DELETE /api/progress`, gated by SWA's
  `authenticated` route rule and validated against `src/lib/`.
- `src/lib/principal.js` — decodes the SWA `x-ms-client-principal` header.
- `src/lib/validate.js` — payload validation (size, schema, known slugs).
- `src/lib/rateLimit.js` — pure rolling-hour + daily write caps (persisted per user).
- `src/sites.json` — allowed slugs; regenerated by `pnpm extract` at the repo root.

## Local development

```sh
npm install                                    # in api/
pnpm dlx azurite                               # Table Storage emulator
pnpm dlx @azure/static-web-apps-cli start http://localhost:5173 --api-location api
```

The SWA CLI's auth emulator lets you sign in as fake GitHub users to test sync and
per-user isolation without a real GitHub app.

## Deploying (manual, one-time — not run by this repo's automation)

These steps create billable Azure resources; run them yourself in the Azure Portal / CLI:

1. Create an Azure Static Web App (Free tier), linked to this GitHub repo. Azure offers
   to generate a GitHub Actions workflow — the one already committed at
   `.github/workflows/azure-static-web-apps.yml` matches what it would create (pnpm
   build, `api_location: api`, `skip_api_build: true`); reuse it rather than letting
   Azure add a second one.
2. Add the `AZURE_STATIC_WEB_APPS_API_TOKEN` secret to the repo (Azure gives you this
   when you create the SWA resource, or `az staticwebapp secrets list`).
3. Create a Table Storage account (or reuse an existing Standard LRS one) and a table
   named `progress`.
4. In the SWA resource's **Configuration → Application settings**, add:
   - `TABLES_CONNECTION_STRING` — prefer an account SAS scoped to the Table service
     with an expiry reminder; fall back to the full connection string if SAS rotation
     is too annoying to maintain.
   - `TABLE_NAME` — `progress`.
5. Confirm the table's region matches what `privacy.html` says.
6. Set a $5/month budget alert on the resource group (Cost Management → Budgets).
7. Push to `main` — the workflow builds and deploys automatically from then on.

## Cost

Worst case per abusive account under the caps in `rateLimit.js` (30 writes/hour,
200/day) is about 200 writes + 200 reads/day, roughly $0.0006/day at current Standard
LRS pricing — check Cost Management after the first week to confirm real usage matches.
